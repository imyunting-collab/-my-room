# MY ROOM｜我的像素生活

> 把喜歡的生活，一點一點住進來。

閱讀養成 × 像素生活 × 房間裝潢 × 戀愛互動。手機優先的繁體中文 PWA，所有資料存在裝置本機（IndexedDB），不需要帳號、不需要網路、不呼叫任何付費 API。

主角是 **99**，男主角是 **陳卷毛**。兩人的像素角色都是用程式逐格繪製的原創 16-bit 像素圖（`src/sprites/characters.ts`），依照使用者提供的照片與角色設定圖的特徵：

- 99：棕色側分短鮑伯、條紋髮夾、棕色印花大學 T、奶油蕾絲領、棕／藍格紋寬褲、厚底運動鞋、黑色斜背包＋兔兔吊飾。
- 陳卷毛：中分蓬鬆中長髮、黑框眼鏡、黑色運動髮帶（不含任何品牌標誌）、黑色寬鬆上衣、黑白毛巾、灰色寬褲、黑白運動鞋、黑色背包、智慧手錶。

## 啟動、測試、建置

需要 Node.js 18 以上。

```bash
npm install          # 安裝 react、esbuild、typescript、playwright
npx playwright install chromium   # 第一次執行測試前需要
npm run dev          # 開發伺服器 http://localhost:5173
npm run typecheck    # TypeScript 檢查
npm run build        # 型別檢查 + 正式建置到 dist/
npm test             # 建置後在 Chromium 跑單元測試 + iPhone 畫面端對端測試
npm run preview      # 用 http://localhost:4173 預覽 dist/
```

## 部署（GitHub Pages）

`dist/` 是純靜態檔案，使用 hash 路由（`#/room`），可以放在任何 HTTPS 靜態主機的任意子路徑。

1. `npm run build`
2. 把 `dist/` 的內容推到 GitHub repo 的 `gh-pages` 分支（或用 GitHub Actions 上傳 `dist/` 當 Pages artifact）。
3. Repo → Settings → Pages，來源選 `gh-pages` 分支根目錄。
4. 打開 `https://<帳號>.github.io/<repo>/`。

Service Worker 只在 HTTPS 下註冊，部署後即可離線使用。

## iPhone 安裝

1. 用 **Safari** 打開部署後的網址。
2. 點「分享」→「加入主畫面」→「加入」。
3. 之後從主畫面圖示打開，全螢幕、可離線。

> Safari 分頁和主畫面 App 的資料是分開存放的，請固定從同一個入口使用，或用備份檔轉移。

## 本機資料與備份

- 書籍、閱讀紀錄、照片（以 Blob 保存）、日記、聊天、戀愛紀錄全部存在這台裝置的 IndexedDB，**不會上傳到任何伺服器**。
- 本機保存 ≠ 跨裝置同步。換手機、清除 Safari 資料或刪除主畫面 App 之前，請到「設定與備份 → 匯出完整備份」下載 JSON 檔。
- 匯入時會先驗證格式並顯示摘要（每個資料表幾筆、幾筆已存在、這個備份是否匯入過），可選擇「合併」、「覆蓋」或「取消」。整個還原在單一 transaction 內完成，失敗時原有資料不會被改動；合併時不會重複發放知識幣。

## 技術架構

- React 19 + TypeScript，esbuild 打包（`scripts/build.mjs`），自製 hash router。
- 資料層 `src/db/idb.ts`：輕量 IndexedDB 封裝，提供 Dexie 類似的能力（版本化 schema migration、typed store、跨 store transaction、live query 更新）。Schema v1（閱讀核心）→ v2（生活）→ v3（設備與戀愛），升級只新增、不刪資料。
- 商品定義（家具、服裝、食物、植物、設備）是程式內的靜態資料（`src/data/catalog.ts`），使用者擁有的物品、位置、狀態存在 IndexedDB。
- 所有像素美術（角色、家具、植物、食物、窗景、圖示）都在 `src/sprites/` 用 canvas 程式繪製並快取。
- PWA：`public/manifest.webmanifest`、App 圖示、建置時產生的預快取 Service Worker（`src/sw-template.js`）。

> 開發環境說明：這個版本是在無法連到 npm 的環境裡完成的，所以沒有使用原規格建議的 Vite、Dexie、Vitest／React Testing Library，改用 esbuild、自製 IndexedDB 層與 Playwright 在真實 Chromium 中測試。`package.json` 已列出標準依賴，在一般電腦上 `npm install` 即可。

## 測試涵蓋

`npm test` 會跑 40 項測試，包括：書架不重複、閱讀紀錄增修刪、知識幣不重複發放、連點不重複扣款、餘額不為負、未解鎖不能買、日夜區間與跨午夜、獨立換裝、三台設備共用日記、冰箱庫存、植物依時間成長且不會枯死、到訪／共同用餐扣庫存／離開、備份還原（含照片與戀愛資料、合併不重複、失敗不破壞資料）、v1→v3 升級保留資料，以及 iPhone 畫面上的實際操作流程（首頁真實時間、新增書籍與紀錄、坐下起身、購買擺放家具、換裝、開電腦／平板／手機、電腦寫日記手機看得到、聊天、通話、邀請陳卷毛、抱抱親親姿勢、食物不足不能吃飯、送他回家後消失、戀愛日記增修刪、種植物澆水、重開後資料仍在、無水平溢出、無 JS 錯誤）。

## 尚未完成／已知限制

- 角色動作是「姿勢切換＋走路兩格動畫」，不是每個動作都有完整逐格動畫；擁抱、親親是兩位角色各自的姿勢靠在一起呈現。
- 陳卷毛的側面與背面造型、以及部分服裝在側面／背面的細節比正面簡化。
- 家具擺放是「點選位置」放置，沒有拖曳。
- 沒有跨裝置同步（依規格以備份檔轉移）。
- 書籍封面需自行拍照或上傳，沒有線上書目查詢。
